## Plan: Gold-State Ownership Migration

Adopt the gold-standard doc as the target contract, not just as inspiration: delete the `repl_state*` facade, move state into domain owners, require by-value reads plus named mutators, make UI renderers pure snapshot consumers, and add ratcheting checks before any behavior changes. The merged plan keeps one extra architectural slice from the earlier draft: move all cross-layer input routing into `imrepl_ctrl.c`, because state ownership alone does not satisfy the goal that the controller is the only mixed-layer module.

Incorporate the gold-standard ratchets up front: write-through-view detection, flat-view-type checks, by-value snapshot return checks, UI renderer signature checks, renderer purity checks, output-actualization checks, `_mut()` usage ratchets, `repl_state.c` size ratchets, facade-include bans in views, domain encapsulation checks, and the focused cursor-pixel encapsulation check. **Verification**
1. Add `check-state-ownership` in Stage 0 and keep it green thereafter. It should include the gold-standard checks for write-through-view, flat-type snapshots, by-value snapshot returns, renderer signature shape, renderer purity, output actualization, `_mut()` count ratchets, `repl_state.c` shrinkage, facade include bans in views, domain encapsulation, and cursor-pixel encapsulation.
2. For each owner migration, tighten the corresponding baseline or allowlist in the same commit. A migration that does not reduce or hold the contract surface is incomplete.
3. Add focused fixture-based tests as the owner pattern lands. Stage 1 should add a small help-overlay test; Stage 4 should add a code-panel render-output test plus a controller actualization test; later UI snapshot conversions should each add a fixture-based renderer test that asserts on `Ui*Output` when present.
4. Add controller input-routing tests in Stage 6 so key and mouse precedence across help, search, menus, color picker, variable panel, code panel, and camera are verified after the controller absorbs the mixed-layer input chain.
5. Keep the existing focused suites running throughout: `make test_repl_code_panel_layout`, `make test_repl_code_panel_document`, `make test_scene_render` plus `./test_scene_render`, and `make test-stubs TEST_JOBS=4`, in addition to `make test`.
6. Final exit criteria: no production `repl_state_*` references, no public view or snapshot type with mutable pointer fields, only `imrepl_ctrl.c` composes across domains, every UI render entry point matches one of the two canonical signatures, every `Ui*Output` field is actualized by the controller, and the allowlists in the state-ownership checks are empty.

**Decisions**
- Incorporate the gold-standard doc as the target architecture, not merely as an optional refinement.
- Keep the gold-standard help-first pilot and small-to-medium-to-large domain migration ordering; it is more practical than starting with the code panel immediately.
- Keep the gold-standard render-output contract: render-produced data flows through `Ui*Output` and controller actualization, never direct setter calls from renderers.
- Retain the earlier plan’s explicit controller input-routing stage, because deleting the facade does not by itself make `imrepl_ctrl.c` the only module that knows about everything.
- Treat `repl_state*` as temporary migration scaffolding only; the final production tree deletes it completely.
- Prefer one domain per commit for Stage 3 and Stage 5 migrations so ratchets, check tightening, and review remain tractable.
